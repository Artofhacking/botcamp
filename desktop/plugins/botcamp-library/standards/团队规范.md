# 团队规范

> 文档库是团队唯一的持久知识库。聊天记录不是知识库；需要长期保留、复用、交接的内容，必须落到文档里。

## 1. 什么时候写文档

以下内容必须写进文档库：

- 账号定位、目标受众、平台策略、更新节奏
- 选题库、内容日历、标题与脚本
- 视觉规范、封面方案、素材说明
- 数据复盘、增长实验、竞品拆解
- 团队协作流程、交付标准、SOP
- 用户明确要求“保存 / 整理 / 写成文档”的内容

以下内容留在聊天里即可：

- 一次性的讨论、临时问答
- 还没有结论的头脑风暴
- 不能公开的密码、Cookie、私信、客户隐私

## 2. 文档库怎么用

- 一篇文档只讲一个主题，避免大杂烩。
- 一个主题只保留一个 canonical 文档；有新结论时原地更新，不另建“最终版 / 最终版2”。
- 不使用 frontmatter，不写 YAML 头。
- 不做版本历史；需要保留的旧结论写进正文的“变更记录”小节，而不是复制整篇文档。
- 文件路径和文件名就是真实文件系统名称，文档树显示实际名称。
- 新建文档放在 `docs/<slug>/index.md`；单篇短文档也可以直接放 `docs/<name>.md`。
- 文档内图片、视频放在这篇文档的 `assets/` 下；跨文档复用的原始素材放 `media/`。
- 图片和视频在正文中用相对路径引用；图片居中显示，视频不自动播放。
- 删除文档时进入 `.trash/`，不要直接物理删除。

## 3. 标准结构

新文档从 [文档模板](botcamp://doc?path=docs%2F%E5%9B%A2%E9%98%9F%E8%A7%84%E8%8C%83%2F%E6%96%87%E6%A1%A3%E6%A8%A1%E6%9D%BF.md) 开始，按主题删减，不要求每节都填满。

最低要求：

1. 标题
2. 一句话结论
3. 背景与目标
4. 核心内容
5. 执行清单
6. 风险与待确认
7. 相关文档

## 4. 内容标准

- 只写最终稿；过程稿、废弃方案不要留在文档库里。
- 先给结论，再给依据；避免空泛的“要重视 / 要优化”。
- 所有建议必须能执行：写清楚谁、做什么、什么时候、交付什么。
- 平台相关的内容写清楚平台、账号、受众、格式和限制。
- 数据结论必须带时间范围和口径，不能只写“效果不错”。
- 涉及事实、政策、平台规则时，标注来源和核对时间；不确定就写“待确认”。

## 5. 链接规范

- Bot 创建或更新文档后，必须把接口返回的 `value.link` 原样给用户，不能只给路径，也不能自己拼链接。
- 链接格式是 `botcamp://doc?path=<URL 编码后的文档路径>`。
- 只有文档真实存在时才给链接；创建失败或路径不存在时，明确说失败原因。
- 文档内互相引用时使用相对链接；需要让用户直接打开时使用 `botcamp://` 深链。
- 不在文档里放临时内网地址、`127.0.0.1` 链接或会失效的预览地址。

## 6. 安全边界

- 不把密码、API Key、Cookie、登录凭证、私信内容、客户隐私写进文档。
- 不把未公开的个人联系方式、订单、财务数据写进文档。
- 需要引用敏感信息时，只写“见某系统 / 向谁确认”，不复制原文。
- 对外分享前先确认文档里没有内部链接、密钥和客户数据。

## 7. Bot 工作流

1. 开始正式产出前，先读 `docs/团队规范/index.md` 和相关 canonical 文档。
2. 先查重：已有同主题文档就更新，不重复新建。
3. 需要新文档时调用 `/md-reader/create`，拿到 `value.path` 和 `value.link`。
4. 用 `/md-reader/write` 写入完整最终稿；不要只写占位。
5. 回复用户时附上真实 `value.link`；没有链接就说明没有创建成功。
6. 内容涉及图片/视频时，先落 `assets/`，再在正文引用。
7. 任务结束后，把可复用的结论补进 canonical 文档，不把结论只留在聊天里。
